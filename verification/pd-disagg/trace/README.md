# Trace checks

`python3 trace/check.py --out check-output` checks `example.pdt` using the independent
Python descriptor observer, then tests deliberately corrupted/missing observations.
Predictions and hashes are written before checking. `CLOSED` means captured ordered
descriptors and argument arrays agree; it does not prove RDMA visibility.
The example is generated by the CPU fixture in `tests/`, not a production log.
`--require-engine` on this memmove example must be INCONCLUSIVE (no RDMA call capture).

For optional TLC conformance, with Java and `TLA2TOOLS_JAR` set:

```bash
python3 trace/check_rejected.py trace/example.pdt trace-model-output --radix
```

`extract_observed.py` maps successes; `check_rejected.py` also checks rejected calls before/after.
`PdReject.tla` extends rejection checks, not a replacement success model.
The trace core comes from original PdCore SHA256 `05e988a5`; it deliberately differs
from the current `spec/` proof target. That copy was renamed with mechanical reversal and token checks.
No TLC trace run was performed during packaging. Python observation acceptance
must not be relabeled as TLC CONSUMED or as refinement to the newer design model.
P prefix sharing is single-page; concrete slot digests and capture hooks are trusted
boundaries, with possible digest collisions. Missing captures remain inconclusive.
